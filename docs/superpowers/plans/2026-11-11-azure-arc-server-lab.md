# Azure Arc 서버 입문 실습 구현 계획

> **에이전트 실행자:** 필수 하위 스킬은 `superpowers:executing-plans` 또는
> `superpowers:subagent-driven-development`이다. 체크박스로 작업 완료를 추적한다.

**Goal:** Azure 구독만으로 Ubuntu 한 대를 Arc에 연결하고 실제 관리 동작과 정리까지
따라 할 수 있는 한국어 실습 가이드를 만든다.

**Architecture:** 전용 Azure VM을 공식 평가 절차로 외부 서버처럼 준비하고 Arc에
등록한다. Azure Portal과 SSH를 사용하며 별도 애플리케이션이나 IaC 도구는 만들지 않는다.
문서 작성과 과금이 발생하는 실제 배포를 분리한다.

**Tech Stack:** Azure Portal, Ubuntu 24.04 LTS(x64), Windows OpenSSH,
Ubuntu Bash, Azure Connected Machine Agent, Linux Custom Script 확장.

**Spec:** `docs\superpowers\specs\2026-11-11-azure-arc-server-lab-design.md`

## Global Constraints

- 전용 리소스 그룹에 Ubuntu 24.04 LTS(x64) VM 한 대를 둔다.
- 이 구성은 평가·테스트 전용이며 Azure VM의 운영 구성으로 지원되지 않는다.
- SSH 인바운드는 실습자 공인 IP의 `/32`로 제한한다. Arc용 인바운드 포트는 열지 않는다.
- 기존 업무용 VM은 변경하지 않는다. 중첩 가상화는 사용하지 않는다.
- 별도 IaC 도구와 배포 자동화는 도입하지 않는다.
- 예상 비용과 실습 시간을 확인한 후 배포 승인을 받는다.
- 추가 과금 가능 기능을 실습에서 새로 활성화하지 않는다.
- 키·토큰·개인 식별 정보와 다운로드한 온보딩 스크립트는 저장소에 넣지 않는다.
- 실제 배포를 수행하지 않았다면 문서를 실제 환경에서 검증했다고 표현하지 않는다.

## Review Focus

1. 구독 정책이 확장·보안 기능을 자동 설치하거나 권한을 제한하는 경우:
   정책을 임의 해제하지 않고 실습을 중지해 관리자와 확인한다. 작업 1에서 점검한다.
2. Guest Agent 비활성화 전 SSH가 안 되는 경우:
   설정을 진행하지 않아 관리 경로를 잃지 않는다. 작업 1에서 확인한다.
3. 방화벽·재부팅으로 SSH나 평가 환경 설정이 달라지는 경우:
   SSH 허용과 두 IMDS 주소 차단을 재검증한다. 작업 2에 확인 절차를 둔다.
4. 다른 테넌트·구독으로 인증하거나 통신이 막힌 경우:
   `Connected` 성공으로 처리하지 않고 등록 ID와 연결 진단을 확인한다. 작업 2에서 다룬다.
5. VM만 삭제하거나 확장 삭제를 파일 삭제로 오해하는 경우:
   Arc 리소스·디스크·공인 IP 잔존 및 확장 산출물 수명을 구분한다. 작업 2에서 확인한다.

## 파일 구성과 실행 경계

- 생성: `README.md` — 목적, 구성도, 비용·지원 제한, 시작 전 점검,
  Portal 기반 전용 VM 생성과 SSH 접속 확인, 상세 가이드 연결.
- 생성: `docs\hands-on.md` — 평가용 VM 준비, Arc 등록, 검증,
  태그·Custom Script 확장 실습, 실패 진단, 연결 해제와 리소스 정리.
- 기존 설계·계획 문서 외에 실행 코드, 패키지 매니페스트, 테스트 프레임워크를 추가하지 않는다.
- Windows PC 명령은 PowerShell, Ubuntu 내부 명령은 Bash로 구분한다.
  Windows에서 Linux 경로를 실행하게 안내하지 않는다.
- 실제 계정 값은 문서에 저장하지 않는다. 예제 이름은 리소스 그룹 `rg-arc-lab-01`,
  VM 및 Arc 서버 `arc-lab-ubuntu-01`, 사용자 `arcadmin`으로 통일한다.

### Task 1: 전용 VM 생성과 안전한 접근을 안내하는 README

**Files:** 생성 `README.md`.

**Interfaces:**
- 입력: 승인된 설계와 사용자가 확인할 구독·리전·공인 IP·실습 시간.
- 출력: SSH로 접속 가능한 전용 Ubuntu VM. 다음 문서의 진입점은
  `docs\hands-on.md`이며, 아직 Guest Agent나 IMDS는 변경하지 않는다.

- [ ] **1. 현재 공식 조건을 확인한다.**
  설계의 근거 문서에서 OS 지원, 온보딩 역할, 리소스 공급자, 네트워크 요구를 확인한다.
  구독에서 VM 생성 권한과 Arc 등록·확장 관리 권한을 구분해 안내한다.
  강제 정책·유료 플랜·확장 자동 설치가 있으면 중단하도록 적는다.
- [ ] **2. 비용 승인 전 점검 절차를 작성한다.**
  Portal에서 구독·리전을 선택하고 VM 후보의 가격·가용성·vCPU 할당량을 확인하게 한다.
  소규모 실습에 맞는 일반 목적 VM 후보만 비교하되, 확인 전 SKU를 배포 가능하다고 확정하지 않는다.
  VM·OS 디스크·공인 IP 비용과 실습 시간을 함께 표시하고 배포 확인 직전에 승인을 받는다.
  비용 경고는 강제 지출 차단이 아니며 할당 해제 후에도 일부 비용이 남음을 적는다.
- [ ] **3. VM 생성과 SSH 접속 절차를 작성한다.**
  지원되는 Ubuntu 24.04 x64 이미지, SSH 키 인증, 전용 네트워크,
  TCP 22의 실습자 `/32` 제한을 지정한다. 추가 에이전트·관리 기능은 선택하지 않는다.
  Trusted Launch 등의 기본 설정이 확장을 추가했다면 이후 제거 대상인지 확인하게 한다.
  아웃바운드 설치·Arc 통신 경로를 명시하며 기존 VNet의 암묵적 아웃바운드를 가정하지 않는다.
- [ ] **4. 단계별 합격 기준과 중단 조건을 넣는다.**
  PC에서 `ssh arcadmin@<VM_PUBLIC_IP>`로 접속한 뒤 Ubuntu에서
  `cat /etc/os-release`, `uname -m`, `sudo -v`를 실행한다.
  합격은 Ubuntu 24.04, `x86_64`, sudo 성공이다. SSH 실패 시
  `docs\hands-on.md`의 Guest Agent 비활성화 단계로 넘어가지 않는다.
  SSH를 전체 인터넷에 개방하는 해결책은 제시하지 않는다.
- [ ] **5. 문서를 검토하고 변경분을 커밋한다.**
  구성도·링크·명령 실행 위치·비용 승인 게이트가 일치하는지 직접 검토한다.
  문서만 작성했다면 Azure 검증은 미실시로 표시한다.
  `git diff --check`가 성공하면 `README.md`만 명시적으로 스테이징해 커밋한다.

### Task 2: Arc 등록·실제 관리 동작·정리를 안내하는 실습 가이드

**Files:** 생성 `docs\hands-on.md`, 수정 `README.md`의 상세 가이드 링크.

**Interfaces:**
- 입력: 작업 1의 SSH 접속 가능한 VM과 승인된 실습 구독.
- 출력: Arc 연결, 태그 조회, 확장에 의한 파일 생성·확장 제거 확인,
  Arc 연결 해제 및 전용 리소스 그룹 삭제를 수행할 수 있는 가이드.

- [ ] **1. 준비 전 상태와 예상 실패를 기록하는 절차를 작성한다.**
  Ubuntu에서 `command -v azcmagent`로 미설치 상태를 확인하고,
  Portal에서 아직 같은 이름의 Arc 서버가 없음을 확인하게 한다.
  실습 전후 상태를 비교하며 실패를 숨기거나 연결 실패를 정상 상태로 취급하지 않는다.
- [ ] **2. 공식 평가 전용 준비 단계를 작성한다.**
  Azure VM 확장 전부의 제거 완료를 먼저 확인한다.
  SSH 안에서 `sudo systemctl stop walinuxagent`와
  `sudo systemctl disable walinuxagent`를 실행하고 상태를 확인한다.
  `MSFT_ARC_TEST=true`를 현재 실행 환경과 systemd 관리자 환경에 설정한다.
  sudo로 온보딩 스크립트를 실행할 때도 해당 환경 변수를 명시적으로 전달한다.
  UFW 사용 시 활성화 전에 실습자 IP의 SSH 허용을 추가하고,
  `169.254.169.254`와 `169.254.169.253` 아웃바운드를 차단한다.
  인터넷 전체 허용 인바운드 규칙은 추가하지 않는다.
- [ ] **3. 준비 상태와 재부팅 위험의 검증을 작성한다.**
  Guest Agent가 비활성 상태인지, 새 SSH 연결이 가능한지 확인한다.
  IMDS 접근 차단은 짧은 타임아웃과 프록시 우회로 검사하며,
  응답을 받았다면 실패로 판정한다. 인터넷 HTTPS와 DNS는 계속 가능해야 한다.
  재부팅 후에는 서비스·방화벽·평가 환경 변수를 다시 확인하고 필요한 설정을 재적용한다.
  VM Run Command로 복구할 수 있다고 가정하지 않는다.
- [ ] **4. Portal 스크립트로 연결하는 절차를 작성한다.**
  Linux, 공용 엔드포인트, 사용자 수동 인증을 선택하고 온보딩 스크립트를
  저장소 밖에 내려받아 검토·전송한다. 자동 유료 기능 활성화 선택은 하지 않는다.
  SSH 세션에서 평가 환경 변수를 전달해 실행하며 인증 계정·테넌트·구독을 확인한다.
  Arc 메타데이터 리전의 지원 여부도 확인한다.
- [ ] **5. 연결의 합격 기준과 오류 진단을 작성한다.**
  `sudo azcmagent show`의 연결 상태와 구독·리소스 그룹·리소스 ID를 확인한다.
  Portal에서도 동일 Arc 서버가 `Connected`인지 확인한다.
  불일치하면 `azcmagent check --location <ARC_REGION>`과 에이전트 로그를 사용해
  통신·인증·권한을 구분하며 키나 토큰을 진단 결과에 포함하지 않는다.
  `Microsoft.Compute/virtualMachines`와 `Microsoft.HybridCompute/machines`의
  두 리소스가 공존하는 이유를 설명한다.
- [ ] **6. 태그와 실제 확장 실행을 작성한다.**
  Arc 리소스에 `lab=arc-test-01` 태그를 추가하고 저장 결과를 조회한다.
  공식 Linux Custom Script 확장의 Ubuntu 24.04 지원과 과금 조건을 확인한다.
  확장 이름은 `arc-lab-custom-script`, publisher는 `Microsoft.Azure.Extensions`,
  type은 `CustomScript`로 지정하고 지원되는 handler 버전을 확인한다.
  명령은 `printf 'arc-lab-ok\n' > /var/tmp/arc-lab-check.txt`로 한정한다.
  Arc 확장의 provisioning 성공과 SSH의 `cat /var/tmp/arc-lab-check.txt` 출력
  `arc-lab-ok`를 모두 합격 기준으로 둔다. 이후 Arc 확장을 제거하고 목록에서 사라졌는지 확인한다.
  확장 제거는 실행으로 생성한 파일을 되돌리지 않음을 설명한다.
  Portal이 해당 설정을 지원하지 않으면 Azure Cloud Shell의 공식 Azure CLI
  `connectedmachine` 확장 관리 명령을 사용하고, Azure VM 확장 명령으로 대체하지 않는다.
- [ ] **7. 정리와 잔존 자원 확인 절차를 작성한다.**
  SSH로 `sudo azcmagent disconnect`를 실행하고 인증·권한 오류를 확인한다.
  Arc 리소스가 제거됐는지 확인한 다음 Portal에서 전용 리소스 그룹 이름과
  포함 자원을 확인하고 삭제 승인한다. 기존 공유 리소스 그룹은 삭제하지 않는다.
  VM·디스크·공인 IP·Arc 리소스의 부재를 확인하고 청구 정보 반영 지연을 설명한다.
- [ ] **8. 문서 검증과 선택적 실환경 검증을 분리한다.**
  `git diff --check`와 문서 간 이름·링크·명령 순서 검토를 수행한다.
  문서 전용 작업이므로 테스트 프레임워크나 형식적인 정규식 테스트는 추가하지 않는다.
  사용자가 실제 배포 비용을 승인한 경우에만 작업 1부터 따라 하며 각 합격 기준과
  정리 결과를 검증한다. 승인하지 않았다면 실환경 미검증을 명확히 남긴다.
- [ ] **9. 변경분을 커밋한다.**
  `README.md`와 `docs\hands-on.md`만 명시적으로 스테이징하고 커밋한다.
  생성하는 모든 커밋에는 현재 세션의 필수 Copilot 트레일러를 포함한다.

## 자체 검토 결과

- 승인 설계의 VM 한 대, 평가 제약, 연결·태그·확장·정리가 작업 1~2에 포함되어 있다.
- 새 실행 코드나 함수가 없으므로 단위 테스트·함수 인터페이스를 만들지 않는다.
  합격 기준은 실제 SSH, Arc 연결, 확장 실행 결과와 리소스 삭제 여부다.
- 미확정 구독·리전·VM 크기는 배포 전 점검의 필수 입력이며 임의로 배포하지 않는다.
- 문서 작성 완료와 실환경 검증 완료를 구분한다. 비용 승인 전 리소스는 생성하지 않는다.
- 이번 실행은 가이드 작성 범위다. 자동화가 필요해지면 별도 설계 변경을 요청한다.
